# NeuroTechX Asia - China — website

Chinese-first (简体中文) community site for **neurotechx.asia**, modelled on the design system of
[neurotechx.org](https://neurotechx.org) — near-black `#08090d`, cyan `#22d3ee`, Inter/Aldrich,
bordered cards — with the constellation mesh background on the hero and the podcast card.

## Stack

| Layer | Choice | Why |
|---|---|---|
| Framework | **Next.js 16 (App Router, Turbopack) + React 19** | Same stack NeuroTechX itself uses on Vercel; on the patched release line |
| Styling | **Tailwind CSS 3.4** + CSS tokens copied from neurotechx.org | Identical look without copying their code |
| Hosting | **Vercel** (`vercel.json`, `hkg1` region) | `vercel --prod` deploys as-is |
| Content | `content/copy.js` (zh + en), `content/ecosystem.json` | No database needed; regenerate from the research CSV |
| Tooling | **conda env `NTXAsiaWebsite`** (Python 3.11, see `requirements.txt`) | Asset generation and directory data prep |

**Note on pip vs npm:** Vercel runs Node, so the site's dependencies live in `package.json`, not in pip.
The conda environment holds the Python tooling that produces the site's assets and data.

## Deploy to Vercel

Connect the repository in the Vercel team `neuro-tech-x-asia` (Framework preset: Next.js,
root directory `./`, region `hkg1` from `vercel.json`) and set the environment variables from
`.env.example` — `CONTACT_EMAIL` at minimum, `RESEND_API_KEY` when the form should send mail.

Command line, for a project linked by hand:

```bash
npm i -g vercel
vercel login
vercel link          # create or link the project
vercel --prod
```

Then point `neurotechx.asia` at the project: Vercel → Project → Settings → Domains → Add
`neurotechx.asia` and `www.neurotechx.asia`, and apply the DNS records Vercel shows
(A `76.76.21.21`, CNAME `cname.vercel-dns.com`). `.asia` needs an Asia-Pacific registrant or
CEA contact, so register it with the Hong Kong contact rather than a European one.

## The podcast-card background (`/card`)

`components/ConstellationMesh.jsx` is a canvas port of the animated mesh generated by
`_work/make_card_anim_v3.py` in the podcast project — same construction and colours:
vertical gradient `(7,4,15) → (16,9,34)`, breathing violet glow at `(0.5W, 0.46H)`, rotating
light sweep, vignette, two node layers (90 far / 150 near at 1080p) linked by a **Delaunay
triangulation** with a 300 px edge limit, twinkling nodes, and 22 travelling cyan pulses.

Performance: static background baked to an offscreen canvas, edges batched into four alpha
buckets, triangulation refreshed every third frame, DPR capped at 2, loop paused when the tab is
hidden. Measured 23–27 fps in headless Chrome (software rasteriser); 50 fps observed at 701 px
wide with GPU compositing.

`/card` reproduces the master timeline (`0.15 s` logotype build → `2.05–4.72 s` title growth
82 → 116 px → `5.95 s` rule → `6.26 s` tagline) with CSS keyframes only, and a Replay button.
`prefers-reduced-motion` renders a single still frame.

### Corrections applied to the source design

1. **Mesh dip fixed** — in the master the near-layer link alpha follows `0.62 ± 0.38`, so at
   t ≈ 6 s it falls to ~6 % and the background almost vanishes exactly when the title lands.
   The web version clamps the breathing floor at 0.45.
2. **Resolution independence** — every size is in container units (`cqw`), derived from the
   1920×1080 master, instead of hard-coded pixels.
3. **No reflow** — the title growth is a transform, not a font-size change, so the type block
   cannot shift while it scales.
4. **X pulse decoupled** — the master pulses the X at 2.28 s because the old voice-over said
   "X" there (`PULSE_X`/`PULSE_DUR` in the generator). The web version repeats the pulse on a
   9 s loop, so a new take from Kimberley cannot desynchronise it.
5. **Safe area** — the master places the logo with a 3.7 % bottom margin; the web version uses
   4 % so player crop cannot clip it.
6. **Banding** — the ±5 static dither of the master is replaced by a CSS noise overlay (no
   `mix-blend-mode`, which would force a full-card recomposite every frame).


## Ecosystem slider (`/#map`)

The 42 GBA entries are paged horizontally instead of listed in one long grid:

| viewport | cards per slide | layout |
| --- | --- | --- |
| ≥ 1024 px | **6** | 3 × 2 |
| 640–1023 px | 4 | 2 × 2 |
| < 640 px | **2** | 1 × 2 |

`perPage` is derived from `window.innerWidth` in an effect (initial state is 6, so server and
first client render match). `rows` is chunked into pages, each page is a full-width grid, and
the track translates by `-page * 100%` with a 500 ms easing (`motion-reduce` disables it).
Controls: prev/next arrows (disabled at the ends), clickable dots when there are ≤ 8 pages, a
`showing a–b of n` counter, a page label, horizontal swipe (45 px threshold) and
<kbd>←</kbd>/<kbd>→</kbd> when the carousel has focus. Off-screen pages are `aria-hidden` +
`inert` so they are skipped by the keyboard and by screen readers. Changing the city filter or
the breakpoint resets to the first page.

## Events gallery (`/#events`)

`#events` is an auto-playing gallery instead of a card grid: slide 1 is the positioning
statement ("Connecting Asia's neurotechnology community"), then one slide per event. It
advances every 6.5 s, pauses on hover/focus, has a pause toggle, numbered dots, arrows,
<kbd>←</kbd>/<kbd>→</kbd> and horizontal swipe; a thin progress line shows the cycle. All
slides share one grid cell so the card height never jumps while cross-fading, and hidden
slides are `aria-hidden` + `inert`. With `prefers-reduced-motion: reduce` autoplay is off
from the start — the slides are still navigable manually.

## Radiant section glow

`.glow` is one radial-gradient implementation with a position per band, tinted teal-green
(`rgba(45, 212, 191, …)` falling off into the site accent):

| Band | Class | Position |
|---|---|---|
| PILLARS | `glow glow-top` | top centre |
| FIELDS | `glow glow-left` | left edge |
| ECOSYSTEM | `glow glow-both` | both flanks |
| EVENTS | `glow glow-right glow-inside` | right, inside the panel |
| PODCAST | `glow glow-center glow-inside` | middle, inside the panel |
| JOIN | `glow glow-bottom` | bottom edge |

The pseudo-element sits at `z-index: -1` inside `isolation: isolate`, so it paints above the
band's own background and below its content. Framed panels (events, podcast) need the
`glow-inside` variant instead: the wash has to sit *above* the panel background and mesh, so it
takes `z-index: 1` and the panel copy is pinned at `z-10` — otherwise either the panel hides the
glow or the glow tints the text.

## Section system

Every band on the page shares one editorial language, set by the PILLARS block:

- `.section-head` — an accent-dashed eyebrow, a `clamp()` display heading, and a muted
  lead paragraph capped at 48rem.
- `.cells` / `.cell` — horizontal hairline compartments (1px grid borders, no shadows) with
  a top accent line and a short rule that widen on hover. Used by FIELDS and JOIN. Cards were
  removed there on purpose: a page of floating boxes reads as a dashboard, a page of hairlines
  reads as a document.
- `.chip` / `.chip-active` — the ecosystem city filters.
- `.frame` — flat panel with a single gradient hairline across its top edge, used by the
  events gallery and the podcast block; the constellation mesh stays inside as artwork.

The pillars band itself (`.pillar`, `.pillar-icon`) keeps its centred composition, which the
cells deliberately do not copy — left-aligned text under a centred icon reads lopsided.

## Legal pages

`/privacy` and `/terms` are real routes (`app/privacy/page.jsx`, `app/terms/page.jsx`) rendering
`components/LegalPage.jsx` from `content/legal.js`, bilingual, with the language choice shared
with the main site through the `ntx-lang` localStorage key.

The privacy page follows the structure of the NeuroTechX Network Privacy Policy
(https://neurotechx.com/privacy-policy/, last updated October 2020) — the network policy stays
the governing text — and only states what this codebase actually does: two functional
localStorage keys (`ntx-lang`, `ntx-theme`), no analytics, no advertising cookies, contact mail
delivered through Resend, contact mailbox held server-side only. If you add an analytics tool,
a cookie banner or a newsletter provider, update `content/legal.js` in the same commit.

The footer bottom bar is a three-zone CSS grid: copyright left, `ntx-mark.png` centred, legal
links right, stacking to a centred column under 768 px.

## Footer plates

The footer carries two generated rasters, in the spirit of the old `neurotechx.org` footer:

- `public/assets/footer-network.jpg` (1800x760) — a dense web of thin teal strands thrown from
  off-canvas hubs across a near-black field, with star specks and an edge vignette. Sits behind
  the brand, the description and the "Global network" links.
- `public/assets/footer-poly.jpg` (2400x200) — a low-poly teal band behind the copyright strip.

Both are produced by `scripts/make_footer_plates.py` (pure Pillow, seeded, no numpy):

```bash
env -u PYTHONPATH /Volumes/M1EXTSSD/MyApplications/anaconda3/envs/NTXAsiaWebsite/bin/python \
  scripts/make_footer_plates.py
```

`.site-footer` pins its own light text palette and a gradient scrim instead of following the
theme tokens, because the plate is dark artwork in both themes — the same reason the Asia map
keeps its dark plate. Two traps worth knowing: a radial "glow" composite over the whole plate
blends it toward one flat colour and erases the strands (darken the edges with a mask instead),
and a negative exponent (`t ** 1.6` with `t` a hair below zero from integer rounding) raises
`TypeError: ... not 'complex'` — clamp the ramp.

## Light / dark theme

A square icon switch sits in the header, after the language toggle and the "join community" button, and flips the whole page.

- The theme lives on `<html data-theme="light|dark">` and is written by an inline script in
  `app/layout.jsx` **before first paint**, so a returning visitor never sees a dark flash.
  Dark is the brand default; the switch is opt-in and the choice persists in `localStorage`
  (`ntx-theme`).
- `components/ThemeToggle.jsx` only flips the attribute, `color-scheme` and the `theme-color`
  meta. Every colour comes from the `[data-theme="light"]` token block in `app/globals.css`,
  which re-points `--background`, `--foreground`, `--surface-*`, `--border*` and darkens the
  cyan accent to `#0e8fa8` for contrast on paper.
- Two things do **not** invert, because they are artwork: the constellation canvas keeps its
  dark gradient, so `.mesh-layer` is flipped with `filter: invert(1) hue-rotate(185deg)` and
  faded to a texture instead of being hidden; and the Asia map raster stays on its own dark
  plate (`[data-theme="light"] .asia-map`), which reads as a framed chart.
- Card surfaces, tags, arrows and the contact dialog all inherit the tokens, so only the
  hand-picked overrides in that block need maintaining when a component is added.

## Chapter map (`/#chapters`)

A shaded relief-style map of Asia above the fields section, with every NeuroTechX city
coloured by status.

- **Land** is Natural Earth 110m country polygons (public domain), rasterised by
  `scripts/build_asia_map_raster.py` into `public/assets/asia-land.png` at 2200×1404
  (displayed ~1000 px): vertical gradient fill, a coastline band derived from a morphological
  erosion of the mask, a blurred cyan halo, and a faint 10° graticule baked in. The raster is
  used instead of SVG paths because country polygons share borders imprecisely — stroking them
  drew internal frontiers, and filling them produced seams.
- **Cities** live in `content/chapters_asia.json` (lat/lon, projected `x`/`y`, label `dx`/`dy`
  and `anchor`), so adding a chapter is one JSON row. Pins and labels are HTML positioned over
  the raster, which keeps type crisp at any width.
- **Statuses**: `listed` (cyan, on neurotechx.org/community), `forming` (amber, Shenzhen),
  `reboot` (magenta, Singapore). The legend renders only the statuses present.
- Arcs from the Hong Kong hub to every other chapter, drawn as dashed quadratic curves with a
  slow dash animation; they pause under `prefers-reduced-motion` via the global rule.
- The window is lon 45–150°E, lat 55°N–12°S, equirectangular — India and Japan both fit without
  the northward stretch of Mercator.

The roster is sourced from the global community page, which currently lists seven Asian
chapters (Hong Kong, Shanghai, Tokyo, Bangalore, Kolkata, Mumbai, Chennai); Shenzhen and
Singapore are local states, not global ones.

## Contact (`/#join` → 联系我们)

The address is **never present in the HTML, the JS bundle or any API response**. Two modes,
chosen by the server from the environment:

| env | mode | behaviour |
| --- | --- | --- |
| `CONTACT_EMAIL` + `RESEND_API_KEY` | `form` | visitor fills a form; the recipient never leaves the server; `reply_to` is set to the visitor |
| `CONTACT_EMAIL` only | `reveal` | button fetches the address on click, in three integer chunks with per-chunk random offsets, assembles it in memory and offers copy + `mailto:` |
| neither | `none` | the dialog says the channel is being configured — no silent message loss |

```bash
# .env.local (gitignored) or Vercel → Settings → Environment Variables
CONTACT_EMAIL=<the mailbox that should receive the messages>
# RESEND_API_KEY=re_…      # uncomment to switch the dialog to form mode
```

Verified: `curl` of `/` and `grep` of `.next/static` both return zero occurrences of the
address; `POST /api/contact` without the `x-ntx-action: reveal` header never returns it.

Honest limit: in reveal mode the address is obfuscated, not secret — a determined scraper that
executes the page and decodes the numbers can recover it. It stops crawlers that parse HTML and
static JS, which is what harvests addresses in practice. Form mode is the only mode where the
address never reaches the browser. Add a CAPTCHA (Turnstile) or a mail provider if you need
harder guarantees.

Rate limits: 5 messages / IP / 15 min, 10 reveals / IP / hour, 60 messages per instance per
window. They live in memory — fine for a small site; move to Vercel KV/Upstash for hard
guarantees.

## Editorial rules

- All copy is in `content/copy.js`; keep `zh` and `en` in sync.
- Institution entries come only from verified research (each carries a `verified` flag); the amber dot
  means "partially verified", with the reason kept in the source research notes.
- No fabricated chapters, members, contact handles or podcast episodes: Hong Kong and Shenzhen are
  labelled "in formation", contact details are marked as published at launch.

## Icons

`scripts/make_favicons.py` rebuilds the favicon set from the official artwork in `public/assets/`: the
hexagon silhouette is taken from the outer contour of `ntx-logo.png` and the infinity from `ntx-mark.png`,
composited as the printed brand (black hexagon, white glyph) on a light plate so it reads on both light and
dark browser chrome. It writes `favicon.ico` (16/32/48), `icon-192.png`, `icon-512.png` and
`apple-touch-icon.png` (180, opaque, no rounding — iOS masks it). `site.webmanifest` references 192 and 512
and declares a maskable entry. Regenerate with the `NTXAsiaWebsite` env; never hand-edit the binaries.

## Routing and languages

Every page lives under a locale segment — `/zh` (default) and `/en` — generated statically via
`generateStaticParams` in `app/(site)/[locale]/layout.jsx`; `dynamicParams = false` makes any other segment
404. `middleware.js` sends the bare `/` to a locale: an explicit `?lang=` wins, then the `ntx-lang` cookie,
then `Accept-Language`, then Chinese. Legacy paths (`/privacy`, `/terms`) redirect to their `/zh` equivalents,
so old links keep working. `/api` and `/card` are excluded from the matcher, and `/card` carries its own
root layout under `app/(card)/`.

The language switch navigates between the two trees (`swapLocale` in `content/locales.js`) and writes the
cookie, so the next bare-URL visit keeps the reader's language. Metadata is per-locale: each page declares
its own canonical plus `hreflang` for zh-CN, en and x-default (`pageMetadata`), and `sitemap.xml` lists both
trees with their alternates. `<html lang>` is rendered server-side from the route, not patched on the client.
